# 账号质量规则

管理员在「账号管理 → 定时测试」创建或编辑计划，打开「账号质量检测」，填写 Cron 和 1–8 个文本模型。现有计划继续执行连通性测试。打开质量检测后默认仅记录，每个模型每轮产生一次上游请求，可能计费。

探针使用随机整数运算、交替步骤和整除计数题，要求只返回整数。历史逐模型保存题目、标准答案、实际回答、判定和有样本的性能指标。图片、视频、模拟账号以及只提供结构化判定的 TypeSafe 账号不能执行该文本探针。自适应协议账号通过 Chat Completions 执行一次题目。单模型超时为 25 秒。

可选的性能条件取该账号和模型最近 60 分钟已记录的生产请求。首字耗时使用有首 Token 记录的流式请求，输出速度按各请求输出 Token 除以总耗时计算后取平均。HTTP 错误占比使用已记录的上游 4xx/5xx 条数除以这些错误与成功用量条数之和。重试、日志采样及保留策略会影响该比例。每项指标至少需要三个有效样本，缺少样本时只判断可用条件。检查随计划运行，包括账号已隔离期间的复测。

默认连续三轮失败达到处置阈值，连续两轮通过解除本规则的隔离。管理员可调整两个阈值，并选择仅记录、隔离模型、隔离指定分组或暂停账号。每个模型分别计数；同一账号或分组有多个失败模型时，相关处置全部解除后才恢复。请求错误或超时记为无法判定，打断连续计数并保留已有隔离。停用、删除或更改质量规则会释放它原有的隔离。手动禁用、限流和其他规则各自独立。调度缓存通过原有 outbox 刷新，已发出的请求继续执行。
