# 管理员供应商管理

状态：已按授权在 feature/supplier-management 开发，等待功能检查与后续反馈。实际验证记录见 [verification.md](verification.md)。

## 目标与业务关系

管理员按供应商维护上游接入 URL 及多个 Key，查询共享钱包余额和各 Key 的上游计费倍率，继续使用现有账号、本站分组和计费体系。

- 一个供应商维护一个 URL，其下包含多个 Key；这些 Key 属于同一上游登录账号，共享一份钱包余额。
- 每个用于模型调用的 Key 直接使用现有账号记录，保存后同步出现在账号管理中，双向编辑与删除共用同一数据；账号与本站分组继续是多对多关系。
- 一个本站分组可以混用同一供应商或多个供应商的不同上游分组资源，以及自有账号。
- 第一版用手工 Key 名称区分上游分组，不另建上游分组管理层。
- 自有账号继续直接在现有账号和分组流程中管理。
- 旧账号由管理员自行重新设置；本次不提供自动归属或批量迁移功能，也不执行旧账号清理。

## 管理界面

### 供应商列表与详情

- 供应商字段包含名称、URL、启停状态、备注及余额查询配置。
- 列表显示 Key 数量、最近成功查询的钱包余额、查询状态和时间，提供编辑、查看 Key、刷新余额、启停与删除操作。
- 详情内添加、编辑、删除 Key，并设置名称、协议平台、账号倍率和本站分组；现有账号高级设置继续复用。
- 新增供应商 Key 默认开启上游倍率同步及其所需探测，并发数为 100、池模式开启、优先级为 1。账号页选择供应商新增 Key 使用相同默认值；已有账号与管理员显式修改的设置不被覆盖。
- 供应商下的模型调用 Key 仍可从现有账号页查看与管理，并能按供应商筛选。详情提供“在账号管理中查看”入口；创建、编辑和删除共用同一份账号数据，无需额外点击同步或复制凭据。
- URL 由供应商统一管理。变更 URL 后，旗下 Key 的后续请求与查询使用新地址；旧地址的余额及倍率快照失效，界面重新查询。

### 余额查询

- 按所有上游 Key 均不限额度的业务前提，默认自动使用该供应商的已有 Key 查询余额；保存首个 Key 后即可查询，无需额外选择余额来源。
- 保存时优先刚保存的 Key，手动刷新优先最新 Key。失败时最多尝试 3 个 Key，共享 10 秒查询预算，取第一个成功的钱包结果；明确指定的查询来源不自动切换。
- 可选手工指定已有 Key，也可保存单独的专用查询 Key；专用查询 Key 不加入模型调度。没有显式来源时使用自动查询，不额外存储或复制凭据。
- 供应商只显示一份共享钱包余额，不把各 Key 查询结果相加。
- Key 配额、消费窗口、订阅额度与供应商钱包分别识别；缺少钱包字段时显示“暂无法获取”。
- 刷新失败时保留上次成功值及其时间，并标记本次查询失败；从未成功查询时显示未知，不填零。
- 查询失败不阻止保存供应商或 Key，也不单凭查询失败停用可正常调用的账号。
- 保存新增或修改的 Key 时查询一次，并提供手动刷新。第一版不新增供应商定时刷新任务。

### 计费倍率

- 保留账号倍率、本站分组扣费倍率和已有的可选上游倍率同步机制。
- 供应商新 Key 默认开启倍率同步，管理员仍可手动关闭；不会改写本站分组倍率。
- 查询结果展示上游声明倍率。沿用原有规则：未开启倍率同步时保持手工账号倍率；开启后由现有同步逻辑写回。
- 写回使用不含临时高峰叠加的基准有效倍率；界面可另行显示当前高峰影响。
- “上游分组价格”在本次范围内指现有 token 倍率接口提供的数据，不承诺获取完整逐模型价目表或上游分组 ID、名称。
- 不重新定义其他计费公式；批量生图等使用账号倍率的既有路径也须保持原有语义。
- 新的供应商余额刷新不额外开启账号后台探测。原有探测与同步开关的联动行为继续保留，并在界面说明。

## 停用与删除

以下停用、恢复与删除细节作为首版操作规则实现。

- 停用供应商后，旗下模型调用 Key 不再参与新的请求调度。
- 恢复供应商时保留每个 Key 自身原有的启停状态，不把原来停用的 Key 全部开启。
- 删除供应商会一并删除其在本站保存的全部 Key，包括专用余额查询凭据；不要求先手工迁出 Key。
- 删除界面显示供应商名称和将被删除的 Key 数量，避免将整家供应商的操作误认为单 Key 操作。
- 删除关联的是本站接入记录，不调用上游管理接口撤销上游实际 Key。
- 历史用量及账务记录按现有账号删除语义保留；本站分组本身仍存在，关联中的其他供应商账号与自有账号继续可用。
- 供应商级删除须保证旗下 Key 全部退出调度，并处理关联分组、测试计划、派生账号及缓存，不以只隐藏前端记录代替删除。
- 供应商与旗下账号的数据库删除在同一事务中完成，提交后处理缓存失效和调度更新；失败时不报告整家供应商已成功删除。

## 已核实的实现边界

以下依据当前仓库源码核实，未使用真实供应商凭据验证部署兼容性。

- `GET /v1/usage` 接受普通 API Key。普通钱包且 Key 未设置总额度或消费窗口限制时，返回共享用户钱包 `balance`。
- 受限 Key 返回 Key 自身配额或消费窗口；订阅 Key 返回订阅额度。这些字段不能作为供应商钱包余额。
- `GET /v1/sub2api/billing` 返回 token 计费倍率，含分组倍率、用户覆盖、高峰规则和当前有效倍率，不返回上游分组 ID、名称或完整模型价目表。
- 现有倍率写回使用 `resolved_rate_multiplier`。用户倍率覆盖不能再与分组倍率重复相乘。
- 原有“自动探测上游声明倍率”和“同步上游声明倍率”是不同开关，同步开启会连带开启探测。本次供应商新 Key 默认两个开关均开启；普通自有账号保留原有默认。
- 即使没有开启倍率写回，原有新鲜倍率快照仍可能影响 OpenAI 成本调度；不能将其描述为纯展示数据。
- 现有账号倍率并非所有场景都只影响内部成本：批量生图实收及预冻结也使用账号倍率。
- 现有账号删除为软删除，保留历史用量金额和账号 ID；管理用量表查询不到已删除账号时，账号名称显示为 `-`，不能据此承诺保留历史名称展示。
- 现有批量账号删除允许部分成功，派生账号也逐个删除。本次供应商级删除通过独立事务统一处理。

## 验收重点

- 同一供应商多个 Key 共用 URL；不同供应商的同名 Key 不影响彼此；本站分组能混用多个来源。
- 共享钱包只统计一次；受限 Key、订阅 Key、接口不支持、Key 无效及查询超时均有准确状态。
- 保存与手动刷新能更新对应快照；修改 URL 或 Key 后，旧请求的迟到结果不能覆盖新配置的查询结果。
- 已有 Key 与专用查询 Key 两种查询配置均可用，专用查询 Key 不进入请求调度。
- 倍率同步开关、峰时处理、本站用户扣费及批量生图保持既有语义。
- 停用供应商阻断旗下新调度；恢复不覆盖 Key 自身状态；级联删除清理旗下接入并保留历史账务。
- 管理接口由后端验证管理员权限；查询复用现有上游请求约束，响应和日志不泄露完整 Key。
- 页面沿用现有暖色主题、公共组件及中英文文案。
